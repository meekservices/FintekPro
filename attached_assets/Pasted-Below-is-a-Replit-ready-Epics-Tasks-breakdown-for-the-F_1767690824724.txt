Below is a Replit-ready Epics & Tasks breakdown for the FintekPro Financial Data Enrichment Flow, exactly aligned to:
Probe42 as master identity

EPIC 1: Company Identity Master (Probe42 Integration)
Objective
Ensure every company has a single, verified FintekPro identity before any financial data is fetched.
Task 1.1 – Create Company Master Schema
Type: Backend / DB
Create company_master table
Fields:
fintekpro_company_id (UUID)
legal_name
country
cin
isin
pan
probe42_id
identity_confidence
status (ACTIVE | REVIEW | BLOCKED)
created_at
Acceptance Criteria
Company cannot be created without Probe42 reference
fintekpro_company_id is immutable
Task 1.2 – Probe42 Fetch Service
Type: Backend
Build probe42-client service
Fetch:
Legal name
CIN / PAN
Country
ISIN (if available)
Store raw Probe42 response for audit
Acceptance Criteria
Raw response stored in company_identity_raw
Failure does not crash onboarding flow
Task 1.3 – Identity Confidence Engine
Type: Backend
Compute confidence score based on:
CIN present (India)
ISIN present
Legal name completeness
Block enrichment if confidence < 0.80
EPIC 2: External Identifier Mapping Engine
Objective
Safely map Probe42-verified companies to Finnhub, SimFin, and Yahoo without symbol collisions.
Task 2.1 – External ID Mapping Table
Type: Backend / DB
Create company_external_mapping:
fintekpro_company_id
source (FINNHUB | SIMFIN | YAHOO)
external_company_id
match_method (ISIN | SYMBOL | NAME)
match_verified (boolean)
locked (boolean)
verified_by (SYSTEM | ADMIN)
created_at
Task 2.2 – Auto-Match Engine
Type: Backend
Matching logic:
ISIN → highest priority
Exact legal name match
Fuzzy match ≥ 90% (log warning)
Exchange suffix validation (.NS, .BO, NASDAQ)
Acceptance Criteria
Auto-matches are not locked
Admin verification required for lock
Task 2.3 – Admin Verification UI (Minimal)
Type: Admin UI
View proposed matches
Approve / Reject
Lock mapping with reason
EPIC 3: Financial Source Connectors
Objective
Fetch raw financial data independently from each source.
Task 3.1 – Finnhub Financial Fetcher
Type: Backend
Endpoints:
Income statement
Balance sheet
Cash flow
Support quarterly & annual
Rate-limit safe (retry + backoff)
Task 3.2 – SimFin Financial Fetcher
Type: Backend
Support:
Bulk CSV ingestion (cron)
API fetch (on demand)
Store restatement-adjusted values
Task 3.3 – Yahoo Finance Adapter (Unofficial)
Type: Backend
Read-only adapter
Used only if:
Finnhub + SimFin both missing metric
Auto-tag as LOW_CONFIDENCE
EPIC 4: Financial Normalization & Merge Engine
Objective
Convert raw source data into one canonical FintekPro schema.
Task 4.1 – Canonical Financial Schema
Type: Backend / DB
Create company_financials table:
Revenue
EBITDA
PAT
EPS
Total Assets
Total Liabilities
Net Worth
Total Debt
Currency
Period
Confidence Score
Locked Flag
Task 4.2 – Metric-Level Merge Logic
Type: Backend
Rules:
SimFin → highest priority
Finnhub → second
Yahoo → last (flagged)
Allow mixed-source per metric
Task 4.3 – Derived Metrics Engine
Type: Backend
Compute EBITDA if missing
Compute Net Debt
Validate negative / abnormal values
EPIC 5: Confidence Scoring & Validation
Objective
Quantify trustworthiness of financial data for AI and advisory usage.
Task 5.1 – Metric Confidence Model
Type: Backend
Base confidence:
SimFin: 0.95
Finnhub: 0.90
Yahoo: 0.70
Aggregate to period confidence
Task 5.2 – Anomaly Detection
Type: Backend
Flag if:
15% variance between sources
Sudden YoY jump without explanation
Trigger admin alert
EPIC 6: Audit & Provenance Logging (SEBI-Critical)
Objective

Task 6.1 – Audit Log Schema
Type: Backend / DB
Create financial_audit_log:
Company ID
Metric
Value
Period
Source
Probe42 reference
Used in (AI / Report / Advisory)
Timestamp
Task 6.2 – “Why This Number?” API
Type: Backend
Return:
Source
Retrieval time
Confidence
Override history

Task 7.2 – Fetch Deduplication
Type: Backend
