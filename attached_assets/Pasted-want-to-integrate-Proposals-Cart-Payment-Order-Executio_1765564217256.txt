✅ FINTEKPRO: MUTUAL FUND ORDER WORKFLOW
Proposal Tab → Cart → Payment → Order Execution
======================================================
1. FLOW OVERVIEW (High Level)
======================================================
Step 1 — Client or Agent initiates order
→ Order is saved as Proposal (not live order yet).
Step 2 — Client reviews Proposal
→ Sees AI-generated insights
→ Sees Agent-provided reasoning
→ Approves OR edits OR rejects
Step 3 — On Approval → Proposal moves to Cart
→ Cart is now a final “Ready to Purchase” basket
Step 4 — Client makes payment
→ Payment gateway → mandate → UPI → Netbanking
→ On success → execute real MF order
Step 5 — Order is sent for Execution
→ BSE Star MF / RTA Integration
→ Units allotted → contract note generated
→ Portfolio updated

3. STEP-BY-STEP LOGIC (DEVELOPMENT SPEC)
======================================================
----------------------------------------
⭐ STEP 1 — CLIENT CREATES ORDER
----------------------------------------
Client initiates an MF Buy Order from scheme page or holdings.
Backend action:
POST /proposals
Payload:
client_id
scheme_id
order_type = BUY / SIP
amount
recommended_by = CLIENT
status = PROPOSAL_PENDING
metadata (source=client-ui)
System stores proposal in:
proposals table
----------------------------------------
⭐ STEP 2 — AGENT AND AI AUTO-ENRICH PROPOSAL
----------------------------------------
Your system now generates AI recommendation text:
Why this fund?
Risk–return match
Performance insights
Asset class suitability
Agent can also review & modify proposal before client sees it.
Proposal now contains:
agent_comment
ai_comment
suggested_amount (optional)
risk_suitability tag
Proposal status remains:
PROPOSAL_PENDING
----------------------------------------
⭐ STEP 3 — CLIENT REVIEWS PROPOSAL AT
/cart?view=proposals
----------------------------------------
UI Requirements (for your developers):
Proposal table must show:
Scheme	Amount	AI Insight	Agent Note	Risk Level	Action
ABC Flexi Cap Fund	₹50,000	"Strong long-term growth"	"Suitable for 5+ yrs"	Moderate	[Approve] [Edit] [Reject]
When client clicks Approve:
Backend:
PATCH /proposals/{id}
status = APPROVED_BY_CLIENT
Then system automatically:
Creates a Cart Item from the proposal
Moves it into:
cart_items table
status = CART_READY
Proposal status:
MOVED_TO_CART
If client clicks Edit:
Open an edit form
On submit → update proposal
Status stays in PROPOSAL_PENDING
If client clicks Reject:
Backend:
status = REJECTED_BY_CLIENT
Proposal disappears from actionable UI.
----------------------------------------
⭐ STEP 4 — CART TAB (FINAL ORDER REVIEW)
----------------------------------------
When items move to Cart:
UI at /cart should display:
Scheme	Amount	Plan Type	Risk	Action
ABC Flexi Cap Fund	₹50,000	Regular	Moderate	[Remove]
Cart Actions:
Remove item → moves back to PROPOSAL stage? NO. Should move to:
DELETED_FROM_CART
Proceed to Payment → moves to payment flow.
Backend object for cart item:
POST /cart/add
{
  cart_item_id,
  proposal_id,
  scheme_id,
  amount,
  status: CART_READY
}
----------------------------------------
⭐ STEP 5 — PAYMENT FLOW
----------------------------------------
Client clicks Proceed to Payment.
Show payment methods based on:
Mandate availability
UPI
Netbanking
Auto-debit for SIP (if applicable)
On Payment Success:
Backend:
PATCH /cart/{id}
status = PAYMENT_SUCCESS
Now trigger actual MF order execution.
----------------------------------------
⭐ STEP 6 — ORDER EXECUTION (REGULATORY)
----------------------------------------
After payment success:
Create Order:
POST /orders/mf
status = ORDER_SUBMITTED
API sends execution request to:
BSE Star MF, OR
RTA API (CAMS, KFin), OR
Internal simulator (if sandbox)
On confirmation from AMC/RTA:
UPDATE order.status = EXECUTED
UPDATE portfolio holdings
GENERATE contract note PDF
SEND email/SMS notifications
----------------------------------------
⭐ STEP 7 — POST-TRADE EVENTS
----------------------------------------
After execution:
Order appears in “My Orders”
Portfolio gets updated with allotted units
Proposal final status becomes:
CONVERTED_TO_ORDER
Cart item becomes:
ORDER_COMPLETED
