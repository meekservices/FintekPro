Below is a Replit-ready conversion of the Config-Based CKYC Provider Switching design into clear Epics → Stories → Engineering Tasks, written so it can be directly pasted into Replit and assigned sprint-wise.
This structure assumes TruthScreen as primary, with admin-configurable fallback CKYC modes, and is SEBI inspection defensible.
REPLIT EPICS & ENGINEERING TASKS
Module: Config-Based CKYC Provider Switching (FintekPro)
EPIC 1: CKYC Provider Configuration Framework
Goal: Decouple CKYC providers from application startup and enable runtime switching without redeploy.
Story 1.1: CKYC Provider Master Configuration
Tasks
Create DB table ckyc_provider_config
provider_code
provider_name
is_enabled
priority
environment
last_health_check
updated_by
updated_at
Seed default providers:
truthscreen (priority 1)
cersai_reference (priority 2)
offline_aadhaar (priority 3)
vkyc (priority 4)
manual (priority 5)
Add migration script
Add soft-delete support (future proofing)
Acceptance Criteria
Providers are stored in DB
No provider hard-coded in codebase
Story 1.2: Runtime Provider Resolution Engine
Tasks
Create resolveCKYCProvider() service
Fetch enabled providers ordered by priority
Validate:
provider enabled
provider health
client eligibility (Aadhaar consent, risk category)
Return first eligible provider
Default fallback = manual
Acceptance Criteria
CKYC provider selected at runtime
No app crash when API credentials missing
EPIC 2: TruthScreen API Integration (Primary Provider)
Goal: Use TruthScreen only when available and healthy.
Story 2.1: TruthScreen Adapter (Lazy Load)
Tasks
Wrap TruthScreen SDK initialization inside provider adapter
Load API keys only at invocation time
Add timeout & retry policy
Normalize TruthScreen response into internal CKYC schema
Acceptance Criteria
App starts even without TruthScreen keys
API failure does not block onboarding
Story 2.2: TruthScreen Health Check
Tasks
Create background health ping
Update last_health_check
Auto-disable provider if repeated failures
Log provider outages
Acceptance Criteria
Admin sees TruthScreen health
Auto-fallback works without manual intervention
EPIC 3: Alternate CKYC Providers (Fallback Modes)
Goal: Ensure regulator-approved continuity.
Story 3.1: CERSAI Reference CKYC Mode
Tasks
CKYC reference input UI
Admin document verification flow
CKYC status = “Verified – CERSAI Reference”
Mandatory admin remarks
Acceptance Criteria
CKYC can be completed without API
Fully auditable
Story 3.2: Aadhaar Offline XML CKYC
Tasks
Upload Aadhaar Offline XML
Validate UIDAI signature
Match PAN name & DOB
Auto-purge XML post-verification
Store hash only
Acceptance Criteria
No Aadhaar number stored
UIDAI-compliant flow
Story 3.3: Video KYC (V-KYC)
Tasks
Live video capture module
Geo-tag & timestamp
PAN shown during call
Admin approval mandatory
Acceptance Criteria
V-KYC accepted as CKYC substitute
Encrypted storage reference only
EPIC 4: Admin CKYC Configuration UI
Goal: Give Admin full runtime control.
Story 4.1: CKYC Provider Settings Screen
Tasks
Toggle provider enable/disable
Change priority via drag-drop
Display provider health
Emergency kill switch
Change audit logging
Acceptance Criteria
Admin changes take effect instantly
All changes logged
Story 4.2: Provider Policy Enforcement
Tasks
Restrict certain providers for high-risk clients
Enforce mandatory fallback order
Block manual CKYC without justification
Acceptance Criteria
Risk-based enforcement works
Policy violations prevented
EPIC 5: Admin CKYC Review & Approval
Goal: Maker-checker compliant CKYC approvals.
Story 5.1: CKYC Review Queue
Tasks
Unified queue for all CKYC modes
Filters by provider, risk, status
SLA countdown timer
Acceptance Criteria
Admin can manage CKYC at scale
Story 5.2: CKYC Decision Engine
Tasks
Approve / Reject / Re-upload / EDD
Mandatory remarks
Risk override reason capture
Acceptance Criteria
No approval without remarks
Full traceability
EPIC 6: CKYC Audit Trail & Inspection Mode
Goal: Zero-friction SEBI inspection readiness.
Story 6.1: Immutable CKYC Audit Logs
Tasks
Log every CKYC state change
Capture:
user
timestamp
IP
device
document hash
Append-only storage
Acceptance Criteria
Logs non-editable
Exportable on demand
Story 6.2: SEBI Inspection Mode
Tasks
Read-only freeze
One-click CKYC evidence export
Provider & fallback disclosure
Approval rationale display
Acceptance Criteria
Inspection demo achievable in <5 minutes

Goal: Permanently fix port 5000 startup failures.
Story 7.1: Startup Safety Refactor
Tasks

Acceptance Criteria

Port opens consistently
