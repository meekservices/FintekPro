📘 README.md — FintekPro Offline & Slow-Internet Resilience (SEBI-Aligned)
1. Objective
FintekPro must remain usable under slow, unstable, or intermittent internet connectivity without compromising:
Transaction integrity
Client consent
Regulatory compliance
Auditability
Offline capability is strictly limited to drafting, viewing, and preparation.
No execution, payment, or regulatory submission is permitted offline.
2. Regulatory Design Principle (Non-Negotiable)
Offline improves user experience, never execution authority.
All SEBI-critical actions require:
Live internet
Server acknowledgment
Audit trail generation
3. Scope of Implementation
Portals Covered
Client Portal
Agent Portal
Admin Portal
Modules Covered
KYC & Onboarding
Risk Profiling
Portfolio (View / Analysis)
AI Investment Proposals
Cart & Checkout (restricted offline)
Tax & Compliance
Reports & Analytics
Admin Configuration
4. Offline Capability Matrix
Role	Allowed Offline	Disallowed Offline
Client	Draft KYC, risk profile, proposal review	Trade execution, payments, final submissions
Agent	Proposal drafting, notes, portfolio analysis	Execution, client consent capture
Admin	Read-only dashboards	Any configuration or approval
5. High-Level Architecture Requirements
5.1 Frontend
Progressive Web App (PWA)
Service Workers for caching
IndexedDB for drafts
Global Network State Manager
5.2 Backend
Server-side execution validation
Idempotent APIs
Action queue reconciliation
Immutable audit logs
6. Compliance Guardrails (Must Be Enforced in Code)
❌ No order execution without network_status = online
❌ No KYC submission without server confirmation
❌ No silent retries for financial actions
✅ Explicit user messaging for queued actions
✅ Full audit trail for offline → online sync
7. Audit & Inspection Readiness
The system must be able to demonstrate:
Who did what
When it was drafted
When it was approved
When it was executed
Network state at each step
8. Success Criteria
App usable on low bandwidth (2G/3G)
Zero data loss on disconnect
Zero offline executions
All sync events auditable
Clear client communication
🧩 TASKS.md — Replit Implementation Task List
Each task below should be treated as an independent Replit ticket.
EPIC 1 — Network Awareness & State Management
TASK 1.1: Global Network State Manager
Detect online / offline / slow network
Expose state via context/store
Trigger UI banners
Acceptance
Network change reflected within 2 seconds
EPIC 2 — PWA & Offline Shell
TASK 2.1: Enable PWA
Register service worker
Cache app shell & static assets
Enable background sync
TASK 2.2: Cache Strategy
Cache menus, navigation, static content
Do NOT cache execution APIs
EPIC 3 — Draft Auto-Save Engine
TASK 3.1: Draft Persistence Layer
Use IndexedDB
Encrypt sensitive drafts
Save every 5–10 seconds
TASK 3.2: Draft Metadata
Each draft must store:
userId
role
module
timestamp
syncStatus
EPIC 4 — Action Queue & Sync Engine
TASK 4.1: Client-Side Action Queue
Queue offline actions
Tag with idempotency key
TASK 4.2: Sync Processor
Trigger on reconnect
Retry with exponential backoff
Surface failures to user
EPIC 5 — Backend Execution Guardrails
TASK 5.1: Server Validation Middleware
Reject execution if:
network_status ≠ online
session invalid
duplicate idempotency key
TASK 5.2: Execution Logging
Log:
IP address
Timestamp
Network state
User role
EPIC 6 — Adaptive Low-Data UI
TASK 6.1: Auto Low-Data Mode
Disable animations
Replace charts with tables
Reduce payload size
TASK 6.2: Manual Toggle
Add “Low Data Mode” in settings
EPIC 7 — Role-Based Offline Enforcement
TASK 7.1: RBAC Matrix
Enforce role × action × network state
Block disallowed actions at UI + API
EPIC 8 — User Communication Layer
TASK 8.1: Standard Status Messages
Implement consistent messages:
Saved locally
Queued for sync
Synced
Failed (retry available)
TASK 8.2: Compliance Messaging
Explicitly state:
“Execution will occur only after internet connectivity is restored.”
EPIC 9 — Audit & SEBI Evidence
TASK 9.1: Immutable Audit Logs
Append-only logs
No update/delete allowed
TASK 9.2: Transaction Reconstruction API
Fetch full lifecycle of any proposal/order
FINAL DEPLOYMENT CHECKLIST (MANDATORY)
 Offline trade execution impossible
 Draft vs execution clearly separated
 All sync events logged
 Role boundaries enforced
 Client disclosures visible
 Ready for SEBI inspection demo
ONE-LINE DEVELOPER RULE
