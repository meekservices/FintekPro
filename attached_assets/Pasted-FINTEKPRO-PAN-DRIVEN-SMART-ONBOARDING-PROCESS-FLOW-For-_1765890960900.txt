FINTEKPRO
PAN-DRIVEN SMART ONBOARDING PROCESS FLOW
(For Replit – Agent Portal & Client Portal)
1. OBJECTIVE

Build a PAN-first onboarding engine that:

Automatically identifies client type from PAN

Determines correct regulatory onboarding path

Supports Smart Mode (auto-fetch) and Manual Mode

Minimises friction for the client

Ensures SEBI / AMFI / KYC / AML compliance

Enables client to complete financial transactions on Fintekpro portals

2. PAN TYPE IDENTIFICATION (FOUNDATION)
2.1 PAN STRUCTURE (INDIA)

PAN Format: AAAAA9999A

4th Character	PAN Holder Type
P	Individual
C	Company
H	HUF
F	Firm / LLP
T	Trust
A	AOP
B	BOI
L	Local Authority
J	Artificial Juridical Person
G	Government

👉 Fintekpro must read the 4th character to classify client type automatically.

3. PAN-BASED CLIENT CLASSIFICATION LOGIC
3.1 System Classification
PAN Type	Client Category
P	Individual (Retail / HNI / sHNI / bHNI)
H	HUF
C	Corporate
F	Firm / LLP
T	Trust
A / B	Association / Body
G / L / J	Institutional / Special

This classification decides the entire onboarding flow.

4. ONBOARDING MODES
4.1 Smart Mode (Default – Recommended)

Uses APIs to auto-fetch data.

Enabled when:

PAN is valid

Client consents to digital onboarding

APIs are available

4.2 Manual Mode (Fallback)

Used when:

API fetch fails

Client prefers manual

Special entity cases (Trusts, Institutions)

6. DETAILED FLOW – INDIVIDUAL CLIENT (PAN = P)
6.1 Step-by-Step (Smart Mode)

Agent/Client enters PAN

System validates PAN format

Fetch from CKYC / PAN APIs:

Name

DOB

Address

KYC status

If CKYC exists → auto-fill profile

If CKYC not found → initiate CKYC creation

Fetch Aadhaar (optional, consent-based)

Perform:

AML / sanctions check

FATCA declaration

Collect:

Mobile

Email

Bank account (penny drop)

Risk profiling questionnaire

Goal & horizon capture

Account activated

Client allowed to transact

6.2 Manual Mode (Individual)

Used if:

CKYC fetch fails

Client opts out

Steps:

Upload PAN

Upload address proof

Upload bank proof

Manual data entry

Video KYC (if required)

Compliance approval

Activate account

7. FLOW – HUF CLIENT (PAN = H)

PAN identifies HUF

Require:

HUF PAN

Karta PAN

CKYC fetch for both

Capture:

Karta details

Declaration of members

Bank account in HUF name

Risk profiling (Karta)

Activate HUF investment account

8. FLOW – CORPORATE / FIRM / LLP (PAN = C / F)
8.1 Smart Mode (Partial)

PAN identifies entity

Fetch from MCA (if available):

Legal name

CIN / LLPIN

Upload mandatory documents:

Certificate of Incorporation

Board Resolution

List of Directors / Partners

PAN & KYC of:

Authorised signatories

Beneficial owners (UBO)

Bank account verification

FATCA / CRS (entity)

Maker–Checker setup

Treasury-only or Investment mode selection

Account activated

8.2 Manual Mode (Corporate)

Used when:

Trusts

NGOs

Special entities

Steps:

Full document upload

Manual verification

Admin approval

Activation

9. FLOW – TRUST / AOP / BOI (PAN = T / A / B)

PAN identifies Trust/AOP

Mandatory uploads:

Trust Deed / Registration

Trustee PANs

UBO identification

Bank verification

Compliance approval

Activate (Treasury mode by default)

Trust	⚠	❌	Treasury only

11. TRANSACTION ENABLEMENT CHECK (CRITICAL)

Before allowing any financial transaction, system must confirm:

✔ PAN verified
✔ KYC completed
✔ Bank verified
✔ Risk profile completed
✔ Disclosures accepted

If any missing → block transaction & show clear message.

16. FINAL INSTRUCTION TO REPLIT

Build onboarding as a PAN-driven decision engine, not a static form.
PAN determines who the client is, what they can do, and how they onboard.
No financial transaction should be possible unless the system explicitly marks the client as “Transaction-Ready”.
