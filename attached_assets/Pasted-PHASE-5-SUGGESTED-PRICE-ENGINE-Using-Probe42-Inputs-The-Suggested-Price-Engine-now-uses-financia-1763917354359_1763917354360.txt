PHASE 5 — SUGGESTED PRICE ENGINE (Using Probe42 Inputs)
The Suggested Price Engine now uses financial data from Probe42 in addition to internal marketplace signals.
Formula Inputs
Landing_Price (Seller feed)
Recent_Deal_Price (Internal Fintekpro deals)
Market_Feed_Price (Optional external data)
Intrinsic_Value (Calculated using Probe42 financials)
Intrinsic value is derived from:
PAT (Probe42 financials)
EPS = PAT / total shares
Sector-level PE benchmark
Intrinsic_Value = EPS × Sector_PE
Base Formula
Suggested Price = 
(Landing_Price * 0.35) +
(Recent_Deal_Price * 0.30) +
(Market_Feed_Price * 0.20) +
(Intrinsic_Value * 0.15)
Risk Adjustment Logic
If Probe42 data shows:
Debt/Equity > 2 OR
Networth < 0
Then apply a discount:
risk_discount = 10%
Suggested_Price = Base_Suggested_Price * (1 - risk_discount)
Backend API
POST /price/suggest
Backend automatically fetches Probe42 intrinsic value using:
company_id
ratios from company_ratios
financials from company_financials

Seller landing price
Buyer max price

✅ PHASE 7 — PROBE42 SYNC (Automated Data Refresh)
Scheduled Task
Run daily/weekly:
Fetch all companies with probe42_company_id
For each company:
Call syncCompanyFromProbe42(company_id)
Fetch updated:
Financials
Ratios
ROC updates
Upsert into DB tables:
company_financials
company_ratios
Store result in probe42_sync_log
Admin Panel → Data Health
Shows:
Last sync time
Status (SUCCESS / FAILED / STALE)
Error messages
If Probe42 fails:
Fintekpro continues using last stored DB values.
UI will show: “Data updated as of DD-MM-YYYY”
✅ PHASE 8 — COMPLIANCE & FALLBACK LOGIC
1. Data Authenticity & Compliance
Probe42 → based on MCA filings → legally acceptable
All data is:
Timestamped
Logged
Stored for 7 years
2. Fallback When Probe42 Fails
If quota exhausted or API down:
Use last saved results in DB.
Mark data as “STALE” in admin.
Continue showing last ratios to buyer with date label.
No break in marketplace functionality.

High debt

Charges on company assets
ROC status changes

Admin → Compliance Flags
