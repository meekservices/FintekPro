🧱 1️⃣ Identity-Centric Access Control
A. User-Level Trust
Each request validated for:
Valid JWT (short-lived, 10–15 mins)
Device binding hash
Risk score validation
IP reputation score
Geo consistency
Session freshness
No session = no access.
B. Service-to-Service Zero Trust
Use mTLS via service mesh (e.g., Istio or Linkerd).
Each container:
Has its own X.509 certificate
Must present valid cert to call another service
Traffic encrypted inside cluster
Even if attacker breaches one container:
→ Cannot move laterally.
🔐 2️⃣ Policy Enforcement Layer (PEP + PDP Model)
Policy Enforcement Point (PEP)
Middleware in each microservice.
Policy Decision Point (PDP)
Centralized policy engine (e.g., OPA – Open Policy Agent).
Example policy:
allow {
  input.user.role == "advisor"
  input.risk_score < 70
  input.device_trusted == true
}
If rule fails → step-up authentication required.
🔍 3️⃣ Device Trust Scoring
Store device registry:
WebAuthn credential ID
Device fingerprint hash
OS version
First seen timestamp
Last risk score
If:
OS downgraded
Jailbroken/root detected
Device not seen in 90 days
→ Trust score reduced.
🧠 4️⃣ Risk-Adaptive Access Control (RAAC)
Combine:
Trust Score = Device + Geo + Behavioral + Transaction Sensitivity
Enforcement Levels:
Risk Score	Action
<40	Allow
40–69	Biometric
70–89	Biometric + OTP
≥90	Block + Manual Review

Query allowlists

🛠 Implementation Logic
Cron Container (Daily 2:00 AM IST)
async function generateAuditExport() {
  const orders = await db.query("SELECT * FROM transaction_log WHERE date = CURRENT_DATE - INTERVAL '1 day'");
  const authLogs = await db.query("SELECT * FROM auth_audit_logs WHERE date = CURRENT_DATE - INTERVAL '1 day'");

  const exportData = {
    generated_at: new Date().toISOString(),
    orders,
    authLogs
  };

  const signed = signExport(JSON.stringify(exportData));

  await uploadToWORMStorage(signed);
}
