Below is a complete design of the FintekPro Institutional Market Data Layer, which sits below the pricing engine and supplies all normalized financial data needed for portfolio valuation, analytics, and compliance.
This is essentially the “data backbone” for the entire FintekPro ecosystem.

2. Data Domains in the Market Data Layer
Institutional platforms divide data into logical domains.
Domain	Data
Reference Data	ISIN, symbol, sector
Market Prices	equity, ETF, derivatives
NAV Data	mutual funds
Corporate Actions	splits, bonus, dividends
Fundamentals	financial statements
Credit Data	bond ratings
Alternative Data	unlisted valuations
3. Security Master (Most Important Component)
Everything must be mapped to a single identifier (ISIN).
Example schema:
CREATE TABLE security_master (
    instrument_id SERIAL PRIMARY KEY,
    isin VARCHAR(20) UNIQUE,
    symbol VARCHAR(50),
    asset_class VARCHAR(20),
    exchange VARCHAR(10),
    currency VARCHAR(10),
    sector VARCHAR(50),
    listing_date DATE,
    status VARCHAR(20)
);
This avoids:
symbol conflicts
duplicate instruments
pricing errors

6. Mutual Fund NAV Engine
AMFI publishes daily NAV.
Python script:
import requests
import pandas as pd

def fetch_nav(scheme_code):

    url = f"https://api.mfapi.in/mf/{scheme_code}"

    data = requests.get(url).json()

    df = pd.DataFrame(data["data"])

    return df

11. Market Data Validation
Institutional platforms validate incoming data.
Example checks:
price deviation > 30%
missing NAV
duplicate instruments
corporate action mismatch
Python example:
def validate_price(price, prev_price):

    change = abs(price - prev_price) / prev_price

    if change > 0.30:
        return False

    return True
