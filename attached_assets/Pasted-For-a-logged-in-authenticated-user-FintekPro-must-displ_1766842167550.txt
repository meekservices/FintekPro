For a logged-in authenticated user, FintekPro must display and operate on three strictly segregated portfolios:
FintekPro Portfolio – Investments executed through FintekPro
Tracker Portfolio – PAN-level consolidated holdings
External Portfolio – Holdings transacted outside FintekPro (derived)
These portfolios must be logically distinct, non-overlapping, and compliance-safe, while remaining reconcilable.
CANONICAL DEFINITIONS (DO NOT DEVIATE)
1️⃣ FintekPro Portfolio
Contains only transactions executed via FintekPro
Source of truth:
FintekPro orders
Execution records
Used for:
Revenue & commission
AI performance attribution
SEBI audit
2️⃣ Tracker Portfolio (PAN-Level)
Contains all holdings linked to client PAN
Includes:
FintekPro Portfolio
External investments
Source of truth:
PAN-linked data feeds (RTA / Depository)
Used for:
Risk profiling
Net-worth
AI analysis & rebalancing
3️⃣ External Portfolio (Derived)
Contains only non-FintekPro holdings
Must never be stored as a primary portfolio
Must always be computed as:
External Portfolio = Tracker Portfolio – FintekPro Portfolio
HARD CONSTRAINTS (NON-NEGOTIABLE)
A holding cannot appear in more than one portfolio
FintekPro Portfolio is always a subset of Tracker Portfolio
External Portfolio is always derived
No execution allowed from Tracker or External portfolios
AI buy/sell recommendations apply only to FintekPro Portfolio
IMPLEMENTATION STEPS
STEP 1: DATA SERVICES
1.1 FintekPro Portfolio Service
Build holdings only from FintekPro transaction tables
No manual or imported data allowed
Output
/portfolio/fintekpro
1.2 Tracker Portfolio Service
Aggregate holdings from:
PAN-linked integrations
FintekPro Portfolio service
Store sync metadata (last updated, source)
Output
/portfolio/tracker
1.3 External Portfolio Computation
Compute dynamically:
external = tracker_holdings – fintekpro_holdings
Match holdings at:
ISIN
Folio / Demat ID
Output
/portfolio/external
⚠️ Do NOT persist external holdings as a primary table
STEP 2: HOLDING MATCHING LOGIC
Matching Rules
Primary key: ISIN
Secondary:
Folio number (MF)
Demat account (Equity / Bonds)
Partial quantity matches must be split correctly
STEP 3: UI IMPLEMENTATION
Portfolio Menu Structure
My Portfolio
 ├── FintekPro Portfolio
 ├── Tracker Portfolio (PAN-Level)
 └── External Portfolio
Display Rules
Each holding shows:
Source badge: FintekPro / External
Quantity
Value
Tooltip explaining each portfolio
STEP 4: AI & ANALYTICS RULES
AI Usage
Fresh investment:
Analyze Tracker Portfolio
Execute into FintekPro Portfolio
Rebalancing:
Analyze Tracker Portfolio
Propose changes only for FintekPro holdings
External holdings:
Advisory insights only (no actions)
STEP 5: COMPLIANCE & AUDIT
Mandatory Labels
Each holding must carry:
source = FINTEKPRO | EXTERNAL
portfolio_view = FINTEKPRO | TRACKER | EXTERNAL
Client Disclosure (Auto-Displayed)
“External holdings are shown for information only and cannot be transacted unless migrated to FintekPro.”
STEP 6: SECURITY & PERMISSIONS
Only authenticated users can access portfolios
No write APIs exposed for Tracker / External
Execution APIs accept only FintekPro holdings
ACCEPTANCE CRITERIA
FintekPro Portfolio matches transaction ledger exactly
Tracker Portfolio shows full PAN-level picture
External Portfolio always equals (Tracker − FintekPro)
No duplicate holdings across portfolios
AI actions restricted to FintekPro Portfolio
Audit export clearly distinguishes all three
FINAL DIRECTIVE FOR REPLIT
“Implement three strictly segregated portfolios—FintekPro (executed), Tracker (PAN-level), and External (derived)—with hard enforcement at data, API, UI, AI, and audit layers. Do not merge or shortcut these definitions.”
