Below is a Replit-ready, cost-optimized instruction set to implement OIDC authentication for FintekPro, designed for India fintech scale, low infra cost, and bank-grade security.






FintekPro – OIDC Authentication Service
Cost-Optimized Implementation Instructions (Replit)
1. Architecture Decision (MANDATORY)
Chosen Approach
Protocol: OpenID Connect (OIDC)
Identity Provider (IdP): Keycloak (Self-Hosted)
Token Type: JWT (RS256)
Deployment: Single shared auth service
Why this is cost-optimal
Zero license cost
Built-in MFA, SSO, RBAC
No per-user pricing
Bank-grade protocol
2. High-Level Architecture
┌────────────┐       ┌────────────────┐       ┌──────────────┐
│  Web/App   │ ───▶  │ Keycloak (OIDC)│ ───▶  │ FintekPro APIs│
│ (Client)   │ ◀───  │ Auth Service   │ ◀───  │ (JWT Verify)  │
└────────────┘       └────────────────┘       └──────────────┘
Keycloak issues ID Token + Access Token
FintekPro services only verify JWT
No session storage in FintekPro
3. Replit Epics & Tasks
EPIC 1: Auth Service Setup (OIDC Core)
Task 1.1 – Provision Auth Service
Create service: fintekpro-auth
Runtime: Docker (preferred) or Node VM
Expose:
https://auth.fintekpro.com
Task 1.2 – Install Keycloak (Minimal Footprint)
Use Keycloak Quarkus distribution
Disable unused modules:
SAML
User federation
Social logins (initially)
Memory target: 512 MB
Task 1.3 – Database Configuration
Use PostgreSQL
Single DB instance
Daily automated backups
EPIC 2: Realm & Client Design (Cost-Optimized)
Task 2.1 – Create Single Realm
Realm name: fintekpro
Avoid multiple realms (reduces memory & ops).
Task 2.2 – Define Clients
Client	Type
fintekpro-web	Public
fintekpro-mobile	Public
fintekpro-api	Confidential
fintekpro-agent-portal	Public
Task 2.3 – Enable OIDC Flows
Authorization Code Flow
PKCE enabled
Refresh tokens ON
Token expiry:
Access Token: 15 min
Refresh Token: 30 days
EPIC 3: Role & Access Model
Task 3.1 – Define Realm Roles
ROLE_CLIENT
ROLE_AGENT
ROLE_ADVISOR
ROLE_ADMIN
ROLE_SUPER_ADMIN
Task 3.2 – Client Roles (API Level)
portfolio.read
portfolio.write
orders.create
reports.view
admin.manage
Task 3.3 – Token Claims Mapping
JWT must include:
sub
email
phone_number
roles
client_id
EPIC 4: FintekPro Backend Integration
Task 4.1 – JWT Validation Middleware
All APIs must:
Validate signature (RS256)
Validate issuer & audience
Validate token expiry
❌ No DB calls for auth
✅ Stateless JWT verification
Task 4.2 – Role-Based Authorization
Map JWT roles → API permissions
Reject unauthorized requests at gateway level
EPIC 5: Frontend Integration
Task 5.1 – Login Flow
Redirect user to:
/authorize?client_id=fintekpro-web
Handle callback:
/auth/callback
Task 5.2 – Token Storage Policy
Web: HTTP-only secure cookies
Mobile: Encrypted secure storage
Never store tokens in localStorage
EPIC 6: MFA & Security (Deferred but Ready)
Task 6.1 – Enable MFA (Optional Toggle)
OTP via email/SMS
Enforce MFA for:
Admins
Agents
Advisors
Task 6.2 – Security Controls
Brute-force protection ON
IP rate limiting ON
Password policy:
12 chars
No reuse (last 5)
EPIC 7: Cost Controls (CRITICAL)
Task 7.1 – Resource Optimization
Single Keycloak pod
Horizontal scale only after 50k MAU
Cache tuning:
Disable persistent sessions
Short-lived tokens
Task 7.2 – Monitoring
Health check endpoint
Alerts on:
Auth failures
Token issuance spikes
Memory pressure
EPIC 8: Compliance & Audit
Task 8.1 – Audit Logs
Log:
Login attempts
MFA challenges
Role changes
Retention: 180 days
Task 8.2 – RBI Alignment
Encrypted PII at rest
Token-based access only
No password handling in FintekPro apps
