Feature: User-Selectable Navigation Bar Position
1. Objective
Allow logged-in users to choose the navigation bar position (Left / Top / Bottom) from Settings → Appearance, with instant UI update, persistent storage, and responsive enforcement.
2. Scope & Applicability
Portal	Applicable	Notes
Client Portal	✅	Full control
Agent Portal	✅	Full control
Partner Portal	✅	Full control
Admin Portal	❌	Fixed left sidebar
3. Data Layer Changes
3.1 Database Schema
If relational DB
ALTER TABLE user_preferences
ADD COLUMN nav_position VARCHAR(10) DEFAULT 'left';
Allowed values
left
top
bottom
3.2 API Contract
Fetch Preferences
GET /api/user/preferences
Response:
{
  "theme": "dark",
  "navPosition": "left"
}
Update Preference
PATCH /api/user/preferences
Payload:
{
  "navPosition": "top"
}
Validation:
Reject values outside [left, top, bottom]
If mobile + left, auto-convert to bottom
4. Frontend Architecture Changes (React / Next.js)
4.1 Create Navigation Layout Variants
/components/layout/
 ├── SidebarLayout.tsx
 ├── TopNavLayout.tsx
 ├── BottomNavLayout.tsx
 └── LayoutResolver.tsx
4.2 Layout Resolver Logic
export function LayoutResolver({ children }) {
  const { navPosition } = useUserPreferences();
  const isMobile = useIsMobile();

  if (isMobile && navPosition === 'left') {
    return <BottomNavLayout>{children}</BottomNavLayout>;
  }

  switch (navPosition) {
    case 'top':
      return <TopNavLayout>{children}</TopNavLayout>;
    case 'bottom':
      return <BottomNavLayout>{children}</BottomNavLayout>;
    default:
      return <SidebarLayout>{children}</SidebarLayout>;
  }
}
4.3 Wrap All Portals with Resolver
Replace existing layout wrapper:
<LayoutResolver>
  <AppRoutes />
</LayoutResolver>
5. Settings UI Changes
5.1 Location
Settings → Appearance
Add new section below Theme selection.
5.2 UI Component
<Card title="Navigation Bar Position">
  <RadioGroup
    value={navPosition}
    onChange={(v) => updatePreference('navPosition', v)}
  >
    <Radio value="left">Left (Sidebar)</Radio>
    <Radio value="top">Top (Header)</Radio>
    <Radio value="bottom">Bottom (Mobile)</Radio>
  </RadioGroup>
</Card>
5.3 UX Rules
Apply changes without page reload
Disable Bottom option on desktop (tooltip: Mobile only)
Show toast on save success/failure
6. Responsive Enforcement Rules
Device	Enforced Layout
Desktop	Left / Top
Tablet	Left / Top
Mobile	Bottom / Top
if (device === 'mobile' && navPosition === 'left') {
  persist('bottom');
}
7. Role-Based Logic
if (user.role === 'admin') {
  forceLayout('left');
}
Hide setting entirely for Admin users
8. State Management
Store preference in:
Global App Context / Redux / Zustand
Load once at login
Cache in localStorage for faster bootstrap
9. Error Handling Standards
Scenario	Action
API failure	Fallback to left
Invalid value	Auto-correct + persist
Network loss	Local cache used
Toast messages:
“Layout updated successfully”
“Unable to save preference. Reverted to default.”
