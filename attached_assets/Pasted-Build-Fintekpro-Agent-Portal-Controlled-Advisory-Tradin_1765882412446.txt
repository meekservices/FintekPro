Build: Fintekpro Agent Portal
(Controlled Advisory + Trading & Sales Enablement)
1. CORE PRINCIPLE (NON-NEGOTIABLE)

The Agent Portal must be built as a CONTROLLED ADVISORY INTERFACE, not a free-form sales or trading tool.

Decision ownership:

✅ System decides why a product is recommended (logic, suitability, optimisation)

✅ Agent explains, contextualises, and assists the client

✅ Client explicitly approves

✅ System executes the transaction

❌ Agents must never override logic, returns, or suitability.

2. WHAT THE AGENT PORTAL IS

The Agent Portal is:

A distribution + explanation layer

A proposal creation & sharing tool

A transaction facilitation interface

A compliance-logged advisory channel

It is not:

A discretionary portfolio manager

A manual trading terminal

A free-text recommendation engine

3. USER ROLES & PERMISSIONS
3.1 Roles
Role	Capabilities
Agent / RM	Create proposals, explain, share, initiate execution
Advisor (RIA)	Same as agent + advanced analytics
Client	View, approve/reject, pay
Admin	Audit, override, lock

All actions must be role-gated.

4. AGENT PORTAL FUNCTIONAL MODULES
4.1 Client Management

Agent can:

Create / onboard client

View client profile:

Client category (Retail / HNI / sHNI / bHNI / Corporate)

Risk profile

Goals & retirement plan

Investable surplus

View existing portfolio (API or upload)

4.2 Portfolio Ingestion

Agent can:

Upload client portfolio (PDF / Excel)

Review parsed holdings

Request client confirmation

Trigger analysis

❌ No analysis without client confirmation.

4.3 Proposal Generation (Advisory Core)

Agent selects:

Proposal purpose:

Fresh investment

Rebalancing

Goal review

Retirement review

Corporate treasury

System must then:

Run suitability checks

Validate goals & horizon

Run optimiser & rebalancer

Generate Draft Proposal

Agent cannot bypass this flow.

5. AGENT EDITING RIGHTS (STRICT CONTROL)
5.1 Agent IS allowed to:

Add an introductory note

Add explanatory commentary

Reorder goals (priority only)

Adjust investment amount (within system-calculated surplus)

Toggle analytics modules (role-based)

5.2 Agent is NOT allowed to:

Change asset allocation logic

Change recommended products

Modify returns, yields, or projections

Remove disclosures

Add ineligible products

Manually “trade” instruments

These must be hard-locked.

6. CUSTOMISABLE ANALYTICS (OPTIONAL, CONTROLLED)

Agent can enable read-only analytics modules:

PE, PB, ROE, ROCE

Alpha, Beta, R²

Past performance

Portfolio overlap

Back-testing (only for sHNI/bHNI)

System auto-injects disclaimers.
Analytics ≠ recommendations.

7. PROPOSAL STRUCTURE (CLIENT-PRESENTABLE)

Every proposal must include:

Client snapshot

Risk profile & horizon

Goals & retirement summary

Current vs recommended portfolio

Buy / Sell / Switch list

Expected returns (Base & Stress)

Risks & liquidity

Mandatory disclosures

Client acceptance section

❌ Agent cannot remove any mandatory section.

8. SHARING & CLIENT INTERACTION

Agents can share proposals via:

Secure view-only link

System-generated PDF

System email

Client can:

Approve

Reject

Ask for clarification

All actions logged.

9. TRADING & SALES FUNCTIONALITY (CONTROLLED)
9.1 How “Trading” Works in Agent Portal

Agents do not place trades manually

Trades are created only from approved proposals

Approved proposal → auto-generated Cart

Cart contains:

Buy orders

Sell orders

Switch orders

Client completes payment / confirmation

System executes orders via integrated APIs

Agent role = facilitator, not trader.

9.2 Sales Enablement Features (Allowed)

Agents may:

Track proposal status

Follow up pending approvals

See conversion funnel

See executed volume (own book only)

Agents may not:

Push products outside optimiser

Force execution

Edit cart contents

10. CORPORATE / TREASURY AGENT FLOW

For corporate clients:

Agent selects treasury objectives

System generates bucketed allocation

Maker–Checker approval enabled

Only debt / treasury instruments allowed

No equity, PMS, AIF, MLD

11. COMPLIANCE & AUDIT (MANDATORY)

Every proposal must log:

Inputs used

Optimisation logic version

Agent ARN / EUIN

Client approval timestamp

Execution status

Retention: 8 years

No proposal deletion allowed — archive only.

12. UI EXPECTATIONS (AGENT PORTAL)
Dashboard

My Clients

Draft Proposals

Pending Client Actions

Executed Proposals

Proposal Editor

Locked system sections clearly marked

Editable commentary panel

Live preview

Execution Tracking

Cart status

Payment status

Order execution status

13. WHAT MUST NOT BE BUILT

❌ Free-text recommendations
❌ Manual trading terminal
❌ Editable return numbers
❌ Product pushing without goals
❌ Execution without client approval
❌ “Assured return” language anywhere

14. FINAL BUILD INSTRUCTION

Build the Agent Portal as a governed advisory + execution facilitation system.
The system decides the recommendation.
The agent explains and assists.
The client approves.
The system executes and logs.

This principle must be enforced at code level, not policy level.
