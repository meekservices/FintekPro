Let’s rewrite the Fintekpro KYC + product access flow with:
PAN verification via Sandbox.co.in API
CKYC fetch via AuthBridge
KRA via Protean (NSDL KRA)
Aadhaar eKYC via Cashfree (where needed)
Loan + Insurance marketplaces included
No social login / No WhatsApp login
Store/products auto-gated based on KYC level
I’ll break it into KYC tiers, process flow, and product gating logic.
1️⃣ Define KYC Tiers for Fintekpro
To link products to eligibility, define internal KYC levels:
Level 0 – Basic Profile Only
Email + mobile + password verified
No PAN, no KYC
Can only browse generic info, maybe read-only product listing (no pricing, no buy/apply)
Level 1 – PAN Verified (via Sandbox.co.in)
PAN verified + basic name match
Suitable for:
Browsing loan marketplace (pre-filtering offers)
Browsing insurance marketplace (showing indicative quotes)
No investments allowed yet (MF/PMS/AIF/unlisted)
Level 2 – Full KYC with CKYC (via AuthBridge) + KRA Verified
PAN + CKYC data (AuthBridge) + KRA (Protean NSDL) is Verified
Suitable for:
Mutual Funds via BSE STAR
PMS / AIF onboarding
Unlisted share buy/sell
Deeper analytics / consolidated portfolio
Your storefront will use these levels to decide what each client can see and do.
2️⃣ Client Login & Entry Point
Login / Signup (No social / No WhatsApp)
Allowed login methods:
Email + password
Mobile + OTP (optional, if you want)
Not allowed:
❌ Google / Facebook / Apple login
❌ WhatsApp login
After login, user lands on Dashboard with a visible KYC Status Banner:
“KYC Status: Not Started / PAN Verified / Fully Verified”
CTA: “Complete KYC” button
This “KYC” button is the trigger for the flow below.
3️⃣ KYC Flow with Sandbox PAN + AuthBridge CKYC
STEP 1 – PAN Verification (Sandbox.co.in)
User clicks KYC button:
User enters PAN + DOB.
Fintekpro → Sandbox.co.in PAN API
Validate PAN format and status
Fetch name / masked details
If success:
Store PAN + verified name
Mark user as KYC Level 1 – PAN Verified
If failure:
Show clear error: “Invalid PAN / PAN not found”
Don’t proceed to next stages
This step unlocks basic browsing of loan + insurance marketplaces (read-only or “pre-qualified check” mode).
STEP 2 – CKYC Fetch (AuthBridge)
Once Level 1 is done, immediately try CKYC fetch under the hood:
Fintekpro → AuthBridge CKYC API with:
PAN
Name
DOB
Optionally Aadhaar (if you choose)
AuthBridge returns:
✅ CKYC record found → KIN, full KYC profile (address, photo, etc.)
❌ No CKYC record found → “Not Found” / failure code
Case A – CKYC Found ✅
Store:
CKYC KIN
Address
Photo
KYC type (Simplified/Normal)
KYC date
Mark client as “CKYC_Fetched = TRUE” (intermediate status).
Go to STEP 3 – KRA validation (Protean NSDL KRA).
Case B – CKYC Not Found ❌
Mark “CKYC_Fetched = FALSE”.
For investment products (MF/PMS/unlisted etc.), force user through Aadhaar eKYC via Cashfree (see Step 3b below).
For loans/insurance, you may still allow some products based on partner requirements (some loan/insurance journeys only require PAN + basic checks).
STEP 3A – KRA Status Check (Protean NSDL KRA) – if CKYC found
Fintekpro → Protean NSDL KRA API using:
PAN + DOB or PAN + KIN
Read KRA status:
Verified / Registered / Green → ✅ Good
On-Hold / Rejected / Not Found → ❌ Needs refresh
If KRA Verified →
Mark KYC Level 2 – Fully Verified
User is now eligible for:
MF via BSE STAR
PMS / AIF
Unlisted shares
Advanced analytics
If KRA On-Hold / Rejected / Not Found →
Go to STEP 3B – Aadhaar eKYC Refresh.
STEP 3B – Aadhaar eKYC via Cashfree (for KRA problems or no CKYC)
Scenario: CKYC not found OR CKYC found but KRA not OK.
User is prompted:
“To invest in Mutual Funds / PMS / Unlisted Shares, please complete Aadhaar OTP eKYC.”
Fintekpro → Cashfree eKYC:
Aadhaar number (or VID)
OTP to user mobile
Cashfree returns:
Verified Name, DOB, Address, Photo
Fintekpro:
Builds CKYC XML package or passes data via KRA partner to CERSAI/CKYC.
Submits updated KYC to KRA (via Protean).
Marks status: “KYC Refresh In Progress”.
Background Job:
Poll KRA status periodically (1–48 hours).
Once KRA Verified:
Upgrade to KYC Level 2 – Fully Verified.
4️⃣ Product Store + KYC-Driven Access Logic
Now link product categories to KYC levels:
Level 0 – Basic
Can see high-level marketing info only (no product details, no quotes).
Level 1 – PAN Verified (Sandbox)
Allowed to:
Browse Loan Marketplace:
See indicative eligibility / interest rate range
Can start application with additional data (income, bureau, etc.)
Browse Insurance Marketplace:
See tentative premiums based on age/income
Can proceed to proposal form (insurer may require more KYC later)
Not allowed:
Mutual Fund / PMS / AIF / Unlisted purchase
Any SEBI-regulated investment execution
Level 2 – Full KYC (AuthBridge CKYC + KRA Verified)
Allowed to:
Create UCC on BSE STAR MF (MF transactions)
Onboard to:
Mutual Funds
PMS
AIF
Unlisted shares marketplace
Access “Holdings import” from CAS / NSDL/CDSL
Access deeper analytics, tax reports
5️⃣ UCC Creation & Mutual Fund Purchase (once Level 2 reached)
Once KYC Level 2:
Fintekpro → BSE STAR AddInvestor API:
Use PAN, Name, CKYC/KRA data, Bank details
Get UCC (Unique Client Code).
User can now:
Place MF purchase orders
Start SIPs
See MF portfolio, etc.
(You already implemented the “PAN → Protean KRA → Cashfree eKYC (if needed) → UCC” logic; we’re just plugging AuthBridge into the front of it.)
6️⃣ Behaviour from Client’s Perspective
On login, client sees:
KYC badge: Not Started / PAN Verified / Fully Verified
When they click:
Loan Marketplace → You check:
If Level 0: ask for PAN (Sandbox) → upgrade to Level 1
If Level 1: allow to explore & apply
If Level 2: allow full flow with more tailored offers
Insurance Marketplace → similar logic as loans
Mutual Funds / Unlisted / PMS →
If Level < 2 → force full KYC (AuthBridge CKYC + Cashfree eKYC if needed + Protean KRA)
If Level 2 → go straight to product listing and BSE STAR flows
This “just-in-time KYC” makes the user feel like KYC is part of the journey, not a block at the very start — but still keeps you fully compliant.
