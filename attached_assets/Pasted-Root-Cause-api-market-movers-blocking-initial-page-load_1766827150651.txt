Root Cause: /api/market/movers blocking initial page load (~1.1s latency)
OBJECTIVE
Reduce dashboard initial load time by:
Removing Yahoo Finance dependency from the critical render path
Caching market movers data
Managing Yahoo authentication correctly
Improving perceived performance without breaking existing flows
TASK GROUP 1: Cache Market Movers API (MANDATORY)
TASK 1.1 – Server-Side Cache for /api/market/movers
Description
Implement an in-memory or Redis cache for market movers data.
Requirements
Cache TTL: 2–5 minutes
Cache key must be environment-aware
Serve cached response immediately if available
On cache miss:
Fetch fresh data
Populate cache
On fetch failure:
Serve stale cache if available
Do NOT block request
Acceptance Criteria
Cached response time < 50ms
Yahoo API not called on every request
Cache hit ratio visible in logs
TASK 1.2 – Background Cache Refresh
Description
Implement non-blocking background refresh for expired cache.
Requirements
Serve last cached value
Refresh asynchronously
Prevent thundering-herd (lock or debounce refresh)
Acceptance Criteria
No concurrent Yahoo calls on expiry
Users never wait for refresh completion
TASK GROUP 2: Yahoo Authentication (Crumb) Lifecycle Fix
TASK 2.1 – Centralized Yahoo Crumb Management
Description
Move Yahoo crumb/token handling to server lifecycle.
Requirements
Fetch crumb once per server instance
Cache crumb with TTL
Refresh crumb proactively before expiry
Share crumb across requests
Explicitly Forbidden
Fetching crumb per request
Fetching crumb per user session
Acceptance Criteria
Crumb fetch frequency ≤ once per TTL window
No authentication delay on normal requests

TASK 3.1 – Remove Market Movers from Blocking Render
