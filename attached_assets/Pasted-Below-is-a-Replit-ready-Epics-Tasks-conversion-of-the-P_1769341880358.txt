🚀 FintekPro PDF Parser Engine v2.0
Replit Epics & Tasks
EPIC 1: PDF Parser v2 Foundation & Backward Compatibility
Objective: Introduce v2 engine without disrupting existing parsing.
Tasks
 Create pdf_parser_v2 service/module
 Implement feature flag (parser_version = v1 | v2)
 Enable dual-run mode (v1 + v2 side-by-side)
 Add result comparison logger (v1 vs v2)
 Define parser error taxonomy
 Centralize PDF ingestion entry point
 Add rollback switch to force v1
 Unit tests for v1/v2 isolation
Deliverable: Safe v2 foundation with rollback
EPIC 2: Document Profiler (Format Learning Engine)
Objective: Automatically identify PDF type & structure before parsing.
Tasks
 Implement PDF text density analyzer
 Extract header/footer repetition patterns
 Detect table presence per page
 Keyword signature detection (CAMS, KFINTECH, Consolidated Account Statement)
 Identify transactional vs summary PDFs
 Capture layout fingerprint (hash + metrics)
 Store profiler output in pdf_profile table
 Confidence scoring for format detection
 Unit tests with uploaded sample PDFs
Deliverable: Reliable PDF type classification
EPIC 3: Layout Segmentation Engine
Objective: Break pages into semantic zones instead of fixed coordinates.
Tasks
 Implement page zoning logic (header/body/footer)
 Detect AMC & PAN header blocks
 Detect scheme/ISIN blocks
 Detect transaction table blocks
 Detect NAV & closing balance blocks
 Normalize multi-page scheme continuation
 Persist block metadata with page numbers
 Fallback logic for irregular layouts
 Regression tests on CAS PDFs
Deliverable: Layout-agnostic parsing capability
EPIC 4: Semantic Block Detection
Objective: Parse by meaning, not by position.
Tasks
 Identify folio number patterns
 Identify scheme name + ISIN patterns
 Identify transaction table headers dynamically
 Detect transaction rows using semantic rules
 Classify financial vs non-financial rows
 Handle CAMS/KFintech wording variations
 Version-tolerant header matching
 Unit tests across CAS versions
Deliverable: Format-resilient semantic parser
EPIC 5: Transaction Table Intelligence
Objective: Extract only CG-relevant transactions.
Tasks
 Normalize transaction types (Purchase, SIP, Switch-In, Bonus)
 Ignore non-financial events (KYC, Address, Broker Change)
 Extract per-row:
Date
Units
NAV
Amount
 Handle multi-line transaction rows
 Handle zero-amount rows (stamp duty)
 Associate transactions with correct folio
 Validate unit balance progression
 Error handling for malformed rows
Deliverable: Clean transaction records
EPIC 6: Purchase Date Resolution Engine (CRITICAL)
Objective: Guarantee correct purchase date for capital gains.
Tasks
 Build purchase date resolution hierarchy
 Treat SWITCH-IN as fresh purchase
 Resolve SIP instalment dates
 Flag unresolved purchase dates
 Tag source of purchase date (CAS / Derived / Manual)
 Block CG computation if date unresolved
 Expose date confidence score
 Unit tests for mixed SIP + lump sum portfolios
Deliverable: CG-safe purchase date engine
EPIC 7: Summary PDF Detection & Enrichment
Objective: Safely handle aggregator-style PDFs without transactions.
Tasks
 Detect absence of transaction tables
 Extract summary holdings (scheme, invested, current)
 Mark holdings as requires_enrichment
 Auto-link with existing CAS data if available
 Raise advisor action flags if unresolved
 Prevent false capital gains computation
 UI flags for low-confidence holdings
 Tests on aggregator PDFs
Deliverable: Zero-risk summary PDF handling
EPIC 8: Holding Lot Builder (Canonical Output)
Objective: Convert transactions into lot-level holdings.
Tasks
 Create holding_lots_v2 schema
 Map transactions → individual lots
 Attach folio, ISIN, scheme metadata
 Compute cost per lot
 Link lots to source PDF + page
 Maintain immutability of parsed lots
 Backfill lots for historical data
 Validation tests for lot integrity
Deliverable: Capital-gain-ready holdings ledger
EPIC 9: Confidence Scoring & Trust Layer
Objective: Quantify reliability of each holding.
Tasks
 Define confidence scoring rules
 Score based on:
Source PDF type
Date resolution method
ISIN match quality
 Persist confidence score per lot
 Expose confidence via API
 UI-friendly warning messages
 Block rebalance for very low confidence
 Test confidence edge cases
Deliverable: Advisor-visible trust signals
EPIC 10: Learning & Format Evolution Store
Objective: Reduce future engineering effort as formats change.
Tasks
 Store layout fingerprints
 Store detected table structures
 Store successful parsing patterns
 Match new PDFs against known patterns
 Auto-suggest parsing strategies
 Admin dashboard for format review
 Version parsing rules safely
 Periodic cleanup of obsolete patterns
Deliverable: Self-improving parser engine
EPIC 11: APIs, Observability & Compliance
Objective: Production-grade readiness.
Tasks
 API: Upload & parse PDF (v2)
 API: Fetch parsed holdings with confidence
 API: Fetch unresolved issues
 Structured parsing logs
 Parsing error dashboards
 Audit trail per PDF & holding
 Performance benchmarks (large CAS)
 Security & PII masking checks
Deliverable: SEBI-safe, observable system
