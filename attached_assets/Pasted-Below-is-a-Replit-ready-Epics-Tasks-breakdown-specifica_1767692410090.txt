Below is a Replit-ready Epics & Tasks breakdown specifically for Free NSE/BSE Filings Ingestion, designed to plug directly into the existing FintekPro FDAL and remain SEBI-inspection defensible.
This is written in implementation order and can be pasted into Replit, Jira, or Linear as-is.
EPIC 1: NSE/BSE Filings Source Integration (Foundation)
Objective
Ingest official Indian exchange disclosures as a free, authoritative fallback for company financials.
Authoritative Sources
National Stock Exchange of India
Bombay Stock Exchange
Task 1.1 – Filings Source Registry
Type: Backend / DB
Create exchange_filing_sources table:
source_id (NSE | BSE)
base_url
supported_document_types (PDF, XBRL, XLS)
active (boolean)
Acceptance Criteria
Sources can be toggled on/off without code changes
Stored centrally for audit
Task 1.2 – Exchange Filing Metadata Schema
Type: Backend / DB
Create exchange_filings table:
filing_id (UUID)
fintekpro_company_id
exchange (NSE | BSE)
filing_type (QUARTERLY | ANNUAL)
financial_type (STANDALONE | CONSOLIDATED)
document_url
filing_date
period_end
document_hash (SHA256)
ingested_at
Acceptance Criteria
Duplicate filings blocked via document_hash
Filing linked to Probe42-verified company only
EPIC 2: Filings Fetcher Service
Objective
Automatically fetch new filings without paid APIs.
Task 2.1 – NSE Filings Fetcher
Type: Backend (Cron + On-Demand)
Fetch corporate results pages
Extract:
Filing URL
Filing date
Result type
Store metadata only (no parsing yet)
Acceptance Criteria
Idempotent fetch
Failure does not block other flows
Task 2.2 – BSE Filings Fetcher
Type: Backend (Cron + On-Demand)
Fetch BSE corporate announcements
Filter:
Financial results only
Persist filing metadata
Task 2.3 – Filing Fetch Scheduler
Type: Backend / Infra
Cron:
Daily for large caps
Weekly for others
Manual refresh via Admin UI
EPIC 3: Document Classification Engine
Objective
Determine how each filing should be parsed.
Task 3.1 – Document Type Detector
Type: Backend
Identify document as:
XBRL
Excel
Searchable PDF
Scanned PDF
Acceptance Criteria
Correct classification ≥ 95%
Classification stored per filing
Task 3.2 – Financial Statement Type Classifier
Type: Backend
Detect:
Profit & Loss
Balance Sheet
Cash Flow
Notes only (ignore)
EPIC 4: Financial Extraction Engine (India)
Objective
Extract only regulator-safe financial metrics.
Task 4.1 – XBRL Parser (Highest Priority)
Type: Backend
Extract:
Revenue
EBITDA
PAT
EPS
Total Assets
Total Liabilities
Net Worth
Acceptance Criteria
Zero OCR
Highest confidence tagging (0.95)
Task 4.2 – Excel Table Extractor
Type: Backend
Parse structured sheets
Map headers → canonical schema
Task 4.3 – PDF Table Extractor
Type: Backend
Extract tables from searchable PDFs
Detect financial rows via keyword mapping
Flag low-confidence cells
Task 4.4 – OCR Pipeline (Last Resort)
Type: Backend
OCR scanned PDFs
Mandatory admin review flag
Confidence capped at 0.85
EPIC 5: Metric Normalisation & Validation
Objective
Convert extracted values into FintekPro canonical financial schema.
Task 5.1 – Canonical Metric Mapper
Type: Backend
Map Indian labels:
“Total Income” → Revenue
“Profit After Tax” → PAT
“Equity Shareholders Funds” → Net Worth
Task 5.2 – Derived Metrics Engine (India)
Type: Backend
Compute EBITDA if missing
Validate:
Negative revenue
EPS mismatch vs PAT
EPIC 6: Confidence Scoring (India-Specific)
Objective
Assign defensible confidence scores to each metric.
Task 6.1 – Source-Based Confidence Assignment
Type: Backend
Source	Confidence
NSE/BSE XBRL	0.95
NSE/BSE PDF	0.90
OCR	≤ 0.85
Task 6.2 – Period Confidence Aggregation
Type: Backend
Compute average metric confidence
Store at period level
