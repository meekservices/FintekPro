Goal
Ensure mutual fund search is always available, AMFI-aligned, and resilient to external API failures, while maintaining high performance and data freshness.
FEATURE 1.1: Search Orchestrator (API-First with DB Fallback)
Task 1.1.1: Create Search Orchestrator Service
Create /services/mfSearchOrchestrator.ts
Responsibilities:
Accept searchQuery
Call AMFI + MFAPI in parallel
Enforce timeout & failure handling
Decide response source (API vs DB)
Acceptance Criteria
Orchestrator returns normalized fund objects
External API calls are parallelized
Failures do not crash the request
Task 1.1.2: Implement External API Parallel Calls
AMFI Search Adapter
MFAPI Search Adapter
Use Promise.allSettled
Timeout: 2–3 seconds max per API
Acceptance Criteria
Partial success is supported
Successful API results are merged & deduplicated
Task 1.1.3: Fallback to Local DB Search
Query mutualFunds table using:
scheme_name ILIKE %query%
amfi_code
fund_house
Trigger fallback when:
All APIs fail
APIs return empty results
Acceptance Criteria
DB fallback returns results if available
Search never returns empty due to API outage alone

Add source flag to each result:
LIVE_API
CACHED_DB
Acceptance Criteria
Frontend can differentiate cached vs live data
