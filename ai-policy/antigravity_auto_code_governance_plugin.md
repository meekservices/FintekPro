## 0. SYSTEM OBJECTIVE

The Antigravity Auto-Code Governance Plugin (ACGP) is a mandatory enforcement layer that intercepts **every line of code** generated by the Antigravity AI coding assistant before it reaches the repository. Its purpose is to:

1. **Intercept** all AI-generated code at generation time and pre-commit
2. **Validate** against FintekPro's full policy stack (GCR + FASP + AI Governance layers)
3. **Auto-fix** any violation that can be deterministically corrected
4. **Block** unsafe or unfixable code from entering the repo or deployment pipeline
5. **Audit** every decision with full traceability for SEBI, RBI, and internal compliance review

> **Non-compliance is not optional. Partial enforcement is a critical failure. Silent rewrites are prohibited.**

## 2. INTEGRATION POINTS

### 2.1 IDE / Antigravity Hook

The plugin hooks into the Antigravity tool call lifecycle **before** any generated code is written to disk.

```
Antigravity tool: write_to_file / replace_file_content / multi_replace_file_content
         │
         ▼
ACGP Interceptor runs synchronously
         │
     ACCEPT → proceed with write
     REWRITE → apply fix, then write
     REJECT → abort write, return violation report
```

**Implementation:**  
- Hook registered in `.vscode/settings.json` under `antigravity.hooks.preWrite`
- Timeout: **200ms hard limit** — if exceeded, plugin BLOCKS by default (fail-closed)

### 2.2 Pre-Commit Hook

Location: `.git/hooks/pre-commit`

```bash
#!/bin/sh
# ACGP Pre-Commit Gate
node plugins/antigravity/cli/validate.js --staged --fail-on=high
if [ $? -ne 0 ]; then
  echo "❌ ACGP: Commit blocked. Resolve violations before committing."
  exit 1
fi
```

**Staged file scanning only** — does not re-scan unchanged files.  
**Scope:** All `.ts`, `.tsx`, `.py` files in staged diff.

### 2.3 CI/CD Pipeline Gate (Railway / GitHub Actions)

```yaml
# .github/workflows/acgp-gate.yml
name: ACGP Compliance Gate
on: [pull_request, push]
jobs:
  validate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Run ACGP
        run: node plugins/antigravity/cli/validate.js --full --env=staging
      - name: Block on Violations
        if: failure()
        run: |
          echo "🚫 ACGP: Merge blocked. See violation report."
          exit 1
```

**Merge is blocked** if the CI gate fails. No bypass is configured on the `main` branch.

## 3. POLICY ENGINE

### 3.1 Rule Types

#### A. Structural Rules
Enforce FintekPro's layered architecture: Routes → Services → Storage. Business logic must never exist in route handlers or middleware.

| Rule ID | Pattern | Severity |
|---|---|---|
| `STRUCT_001` | Direct `db.*` calls in `server/routes/**` | `critical` |
| `STRUCT_002` | Business logic in `middleware/**` | `high` |
| `STRUCT_003` | Missing service abstraction for external API calls | `high` |
| `STRUCT_004` | Circular imports between schema modules | `critical` |
| `STRUCT_005` | `console.log` in production service files (not console.error/warn) | `medium` |

#### B. Financial Integrity Rules
Every financial mutation must be idempotent, ledgered, and reversible.

| Rule ID | Pattern | Severity |
|---|---|---|
| `FIN_001` | Non-idempotent write without `idempotencyKey` | `critical` |
| `FIN_002` | Fund transfer without corresponding audit entry | `critical` |
| `FIN_003` | Order execution without pre-validation suitability check | `critical` |
| `FIN_004` | Missing `try/catch` around payment gateway integration | `high` |
| `FIN_005` | Hardcoded tax rates or fee percentages | `high` |

#### C. Security Rules
Zero tolerance for secrets, unvalidated inputs, or authentication bypass.

| Rule ID | Pattern | Severity |
|---|---|---|
| `SEC_001` | Hardcoded API keys, secrets, or passwords | `critical` |
| `SEC_002` | `req.body` used without schema validation (Zod) | `critical` |
| `SEC_003` | Missing authentication middleware on private routes | `critical` |
| `SEC_004` | SQL-injection-vulnerable raw string concatenation in queries | `critical` |
| `SEC_005` | `eval()` or `new Function()` usage | `critical` |
| `SEC_006` | Unvalidated `req.params` or `req.query` passed to DB | `high` |
| `SEC_007` | Missing `helmet` / CORS configuration on new route groups | `high` |

#### D. AI Governance Rules
AI outputs must never directly trigger financial execution. Explainability is mandatory.

| Rule ID | Pattern | Severity |
|---|---|---|
| `AI_001` | AI output directly passed to order execution without human-in-loop gate | `critical` |
| `AI_002` | Missing `trace_id` in AI model call | `high` |
| `AI_003` | AI response used without validation/schema check | `high` |
| `AI_004` | Missing `rationale` or `explainability` field in AI recommendation output | `high` |
| `AI_005` | AI governance `aiGovernanceEngine.validateAndResolve()` bypassed | `critical` |
| `AI_006` | AI model version not logged before inference | `medium` |

#### E. Audit Rules
Every meaningful system event must produce a structured, traceable log entry.

| Rule ID | Pattern | Severity |
|---|---|---|
| `AUDIT_001` | Missing `trace_id` in service method | `high` |
| `AUDIT_002` | Financial mutation without `console.log`/structured logger call | `critical` |
| `AUDIT_003` | Error caught and swallowed without logging | `high` |
| `AUDIT_004` | Missing `userId` / `agentId` in audit-sensitive operations | `high` |
| `AUDIT_005` | KYC/compliance check result not persisted | `critical` |

## 4. CODE PARSER & ANALYZER

### 4.1 AST-Based Analysis (MANDATORY)

All analysis is performed on the **Abstract Syntax Tree**, not raw text, to prevent false positives from string literals and comments.

```
Input: TypeScript source file
         │
         ▼
TypeScript Compiler API (ts.createSourceFile)
         │
         ▼
AST Node Visitor (custom walkers per rule)
         │
         ▼
Violation Report: [{ rule_id, node, line, column, severity }]
```

**Detected patterns (non-exhaustive):**

| Pattern | AST Detection Method |
|---|---|
| Direct db call in route | `CallExpression` where callee is `db.*` inside `RouteHandler` scope |
| Missing Zod validation | `req.body` property access without preceding `schema.parse()` call |
| Hardcoded secret | `StringLiteral` matching secret entropy heuristic + known key patterns |
| Missing try/catch | `AwaitExpression` inside async function without enclosing `TryStatement` |
| Swallowed error | `CatchClause` body containing no `console.error` / logger call |

### 4.2 Regex Fallback

When AST parsing is unavailable (syntax error in input file), a curated regex suite runs as a fallback. **Regex results are degraded-confidence only** — they are flagged with `"analysis_mode": "regex_fallback"` in the audit log and reviewed more conservatively.

### 4.3 Multi-Language Support

| Language | Parser | Status |
|---|---|---|
| TypeScript (`.ts`, `.tsx`) | TypeScript Compiler API | ✅ Primary |
| Python (`.py`) | `ast` module (subprocess) | ✅ Secondary |
| JavaScript (`.js`, `.mjs`) | Babel parser | 🔄 Planned v1.1 |
| SQL (`.sql`) | Custom tokenizer | 🔄 Planned v1.2 |

## 5. REWRITE ENGINE

### 5.1 Auto-Fix Categories

#### A. Structural Fix — Service Layer Extraction

**❌ Violation:**
```typescript
// server/routes/pricing.ts
app.get("/price", async (req, res) => {
  const data = await db.select().from(listedStocks).where(eq(listedStocks.symbol, req.query.symbol));
  res.json(data);
});
```

**✅ Rewritten to:**
```typescript
// server/routes/pricing.ts
app.get("/price", async (req, res) => {
  const symbol = z.string().parse(req.query.symbol);          // SEC_002 fix
  const data = await pricingService.getStockPrice(symbol);   // STRUCT_001 fix
  console.log(`[pricing] GET /price symbol=${symbol}`);      // AUDIT_002 fix
  res.json(data);
});
```

The extracted service method is scaffolded in the correct service file with a TODO marker for developer review.

#### B. Security Fix — Input Validation Injection

**❌ Missing validation:**
```typescript
const userId = req.params.id;
await db.delete(users).where(eq(users.id, userId));
```

**✅ Injected:**
```typescript
const userId = z.string().uuid().parse(req.params.id);
await userService.deleteUser(userId);
```

#### C. Logging Fix — Structured Log Injection

**❌ Silent operation:**
```typescript
await db.insert(orders).values(orderData);
```

**✅ With audit trail:**
```typescript
console.log(`[orders] INSERT userId=${orderData.userId} amount=${orderData.amount} traceId=${traceId}`);
await db.insert(orders).values({ ...orderData, traceId });
```

#### D. Compliance Fix — AI Governance Gate Injection

**❌ Direct AI execution:**
```typescript
const recommendation = await gemini.generate(prompt);
await executeOrder(recommendation.symbol, recommendation.quantity);
```

**✅ With governance gate:**
```typescript
const recommendation = await gemini.generate(prompt);
const govCheck = await aiGovernanceEngine.validateAndResolve({
  user_id: userId,
  query: prompt,
  ai_output: recommendation,
  user_profile: userProfile,
  trace_id: traceId,
});
if (govCheck.decision === "BLOCK") {
  console.warn(`[ai-gate] BLOCKED trace=${traceId} audit=${govCheck.audit_id}`);
  return res.status(403).json({ error: "AI recommendation blocked by governance engine" });
}
await executeOrder(recommendation.symbol, recommendation.quantity);
```

---

### 5.2 Rewrite Strategy

All rewrites follow these constraints:

1. **Minimal diff** — only the violated construct is modified; surrounding code is untouched
2. **Intent preservation** — the developer's functional goal is preserved; only compliance shape changes
3. **No silent rewrites** — every rewrite is logged to the audit trail AND surfaces a warning to the developer
4. **Re-validation mandatory** — rewritten code MUST pass a second full policy validation pass before acceptance
5. **TODO injection** — where a rewrite requires developer follow-up (e.g., implementing extracted service), a `// TODO(ACGP): [rule_id]` marker is injected

## 6. AI-ASSISTED REWRITE

### 6.1 LLM-Assisted Fixing (Advanced Mode)

For complex violations that require contextual understanding (e.g., multi-file structural refactoring), the plugin invokes the Antigravity model with a constrained prompt:

```
SYSTEM: You are the FintekPro ACGP rewrite engine.
Your ONLY task is to fix the compliance violation described below.
You MUST NOT change any code outside the violation scope.
You MUST NOT introduce new dependencies.
You MUST produce code that satisfies rule [rule_id].

VIOLATION:
  File: {file}
  Lines: {startLine}–{endLine}
  Rule: {rule_id} — {rule_description}
  Severity: {severity}

ORIGINAL CODE:
{code_block}

OUTPUT: Produce ONLY the corrected code block. No explanation.
```

### 6.2 Guardrails on LLM Rewrites

| Guardrail | Implementation |
|---|---|
| Re-validation mandatory | Rewritten output runs through identical policy validation pass |
| Scope limit | LLM is given only the violated function/block, not the full file |
| Diff size limit | LLM rewrite rejected if diff > 40 lines (manual review required) |
| No new imports | Rewrites that introduce new `import` statements are flagged for human review |
| Determinism check | Two LLM rewrite attempts must produce functionally equivalent output |

## 8. ENFORCEMENT LEVELS

### 8.1 Development Mode (`--env=dev`)

- **Warnings** displayed inline in IDE for all violations
- **Auto-fix** applied silently for `low` and `medium` severity
- **Interactive prompt** for `high` and `critical` (developer must acknowledge before fix is applied)
- Pre-commit hook: **warn-only** (does not block)
- Audit log: **local file only** (`/plugins/antigravity/logs/dev.jsonl`)

### 8.2 Staging Mode (`--env=staging`)

- **All violations** produce visible errors in CI output
- **Auto-fix** applied for `low`, `medium`, `high`
- **Hard block** on `critical` — developer must fix manually
- Pre-commit hook: **strict** (blocks on `high`+)
- CI/CD gate: **blocks merge** on any unresolved violation
- Audit log: **remote + local** (pushed to `audit_logs` DB table)

### 8.3 Production Mode (`--env=production`)

- **Zero tolerance** — any violation causes immediate block
- **No auto-fix** — all fixes must be reviewed by a human engineer before re-commit
- Pre-commit hook: **hard block** on any violation severity
- CI/CD gate: **blocks deployment** — no bypass path exists
- Audit log: **immutable** (append-only, signed, archived to cold storage)
- On violation detected in production build: **security alert** sent to `#eng-alerts` Slack channel

## 12. FAILSAFE DESIGN

### 12.1 Primary Failsafe — Fail-Closed

If the ACGP plugin encounters any unhandled error, timeout, or crash:

```
Plugin Error / Timeout
         │
         ▼
DEFAULT ACTION: BLOCK COMMIT / BLOCK MERGE
         │
         ▼
Audit log entry: event="PLUGIN_FAILURE"
         │
         ▼
Alert: #eng-alerts "⚠️ ACGP plugin failure — commit blocked"
```

**There is no fail-open path.** A crashed plugin is treated as a critical violation.

### 12.2 Safe Mode

In the exceptionally rare case where the plugin must be temporarily bypassed for emergency hotfix deployment:

- Requires explicit `ACGP_SAFE_MODE=1` environment variable
- Requires GPG-signed override commit from a CTO-level key
- Limits operations to read-only endpoints only — all write/mutation routes remain blocked
- All safe mode operations produce `event="SAFE_MODE_OVERRIDE"` audit entries
- Safe mode automatically expires after 60 minutes

## 15. FINAL EXECUTION DIRECTIVE

### What Antigravity MUST do when this plugin is active:

Every code generation action taken by Antigravity is subject to this governance layer. When writing code for FintekPro:

1. **Intercept** — all `write_to_file`, `replace_file_content`, and `multi_replace_file_content` operations pass through ACGP validation
2. **Validate** — the full 40-rule policy suite is applied to every generated file
3. **Auto-rewrite** — violations with deterministic fixes are corrected before insertion
4. **Block** — critical violations without safe fix paths cause the generation to stop and a violation report to be returned
5. **Audit** — every decision is written to the audit log before the code write completes
6. **Re-validate** — all auto-fixed code undergoes a second validation pass before final acceptance

### What this system prevents at scale:
